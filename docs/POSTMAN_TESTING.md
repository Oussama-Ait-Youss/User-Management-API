# Postman Testing

## Setup

1. Build and deploy `target/User_Management_API_war_exploded.war` to Tomcat 10.1, or configure IntelliJ to deploy the exploded artifact at the same context path.
2. Start Tomcat and use `http://localhost:8080/User_Management_API_war_exploded` as the base URL.
3. Import `postman/User-Management-API.postman_collection.json` and `postman/Local.postman_environment.json`, or create requests manually.
4. Select the Local environment. Set **Authorization → No Auth** on every request. No credentials or token are required.
5. Use unique emails for create requests because the database persists between restarts.

## Recommended request order

### 1. Check health

`GET http://localhost:8080/User_Management_API_war_exploded/api/health`

Expected: **200 OK**

```json
{ "status": "UP", "application": "User Management API" }
```

### 2. Create an ADMIN

`POST http://localhost:8080/User_Management_API_war_exploded/api/users`

Header: `Content-Type: application/json`

```json
{
  "name": "System Admin",
  "email": "admin@example.com",
  "password": "Admin12345!",
  "role": "ADMIN"
}
```

Expected: **201 Created**, a `Location` header ending in the new user ID, and a response similar to the following. Dates are generated by the application; no password or password hash is returned.

```json
{
  "id": 1,
  "name": "System Admin",
  "email": "admin@example.com",
  "role": "ADMIN",
  "active": true,
  "createdAt": "2026-10-22T10:00:00",
  "updatedAt": "2026-10-22T10:00:00"
}
```

### 3. Create a USER

`POST http://localhost:8080/User_Management_API_war_exploded/api/users`

```json
{
  "name": "Example User",
  "email": "user@example.com",
  "password": "UserPass123!"
}
```

Expected: **201 Created** and `role: "USER"` by default. Save both returned IDs for the remaining requests.

### 4. List active users

`GET http://localhost:8080/User_Management_API_war_exploded/api/users`

Expected: **200 OK**, an array containing both accounts, with no password properties.

### 5. Filter users by role

- - `GET http://localhost:8080/User_Management_API_war_exploded/api/users/role/ADMIN` — expected **200 OK**, an array containing the ADMIN.
- `GET http://localhost:8080/User_Management_API_war_exploded/api/users/role/USER` — expected **200 OK**, an array containing the USER.

### 6. Get an account by ID

- `GET http://localhost:8080/User_Management_API_war_exploded/api/users/{adminId}`
- `GET http://localhost:8080/User_Management_API_war_exploded/api/users/{userId}`

Expected: **200 OK** with a safe user response. Inactive accounts are treated as not found.

### 7. Update the USER

`PUT http://localhost:8080/User_Management_API_war_exploded/api/users/{userId}`

Header: `Content-Type: application/json`

```json
{
  "name": "Updated Example User",
  "email": "updated-user@example.com"
}
```

Expected: **200 OK** with the updated response. The request accepts only `name` and `email`; it cannot change role or password.

### 8. Change the USER password

`PATCH http://localhost:8080/User_Management_API_war_exploded/api/users/{userId}/password`

Header: `Content-Type: application/json`

```json
{
  "currentPassword": "UserPass123!",
  "newPassword": "NewUserPass123!"
}
```

Expected: **200 OK** with a safe user response. An incorrect current password or a new password shorter than 8 characters returns **400 Bad Request**. The ID/current-password check does not authenticate the caller.

### 9. Deactivate the USER

`DELETE http://localhost:8080/User_Management_API_war_exploded/api/users/{userId}`

Expected: **204 No Content** with an empty body. Subsequent normal lookups return **404**, and the user is omitted from lists and role-filter results.

### 10. Verify errors

- Repeat `POST http://localhost:8080/User_Management_API_war_exploded/api/users` with an existing email: **409 Conflict**.
- `POST http://localhost:8080/User_Management_API_war_exploded/api/users` with an invalid email, blank name, or password shorter than 8: **400 Bad Request** with `fieldErrors`.
- `GET http://localhost:8080/User_Management_API_war_exploded/api/users/999999999`: **404 Not Found**.
- `GET http://localhost:8080/User_Management_API_war_exploded/api/users/role/OWNER`: **400 Bad Request**.

The collection's first request is health and its second request creates the ADMIN account. Set a fresh, unused email before rerunning the collection.

Optional root-context check: `GET http://localhost:8080/User_Management_API_war_exploded/` returns **200 OK**:

```json
{ "application": "User Management API", "status": "Running" }
```

## H2 persistence

By default, the physical database file is `%USERPROFILE%\\.user-management-api\\data\\user_management_db.mv.db` (for example, `C:\\Users\\Alice\\.user-management-api\\data\\user_management_db.mv.db`). This absolute path avoids dependence on IntelliJ's or Tomcat's working directory. The application creates the directory if it does not exist. Stop Tomcat before manually copying or replacing the H2 file.

## Build and deploy

```powershell
mvn clean test
mvn package
```

Copy `target/User_Management_API_war_exploded.war` into Tomcat's `webapps` directory and start Tomcat. The expected context path is `/User_Management_API_war_exploded`.
